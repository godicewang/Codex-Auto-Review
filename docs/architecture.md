# Architecture — v0.2

The product is a read-only review loop. Source mutation belongs exclusively to the user's main Codex conversation.

- `hooks/dispatch.mjs`: forwards only lifecycle event, cwd, IDs, user prompt, and tool name/input for mutation attribution. Emits official `hookSpecificOutput.additionalContext` for eligible next-turn advice; no transcript scraping.
- `src/engine.mjs`: per-turn baselines, immutable snapshots, bounded serial queue, cancellations, final findings, persistent queued advice, whole-report batching, session-scoped delivery, and source-change markers.
- `src/advice.mjs`: persistent FIFO report references, v0.2 queue migration, 48,000-character batch construction, and the untrusted-data wrapper.
- `src/entry.mjs`: official project Actions configuration and a stable home-directory launcher that follows the installed plugin on upgrades. Custom setup scripts and actions are preserved.
- `src/prompts.mjs` and `prompts/reviewer.md`: Chinese review contract, language selection, bounded structured input, report/line validation, and untrusted-advice wrapper.
- `src/codex.mjs`: fresh ephemeral App Server session, read-only sandbox, never-approve policy, disabled memories/hooks/plugins/apps/delegation, existing CLI authentication. Progress is discarded by the engine.
- `src/snapshot.mjs`: tracked and untracked source snapshots, no shared index/hard links. Secret filename exclusions, size limits, symlink rejection. No patch application/export writer remains.
- `src/store.mjs`: private state and source blobs; v1 backup and read-only historical migration. Legacy file journals are not replayed.
- `src/cleanup.mjs`: snapshot reachability, terminal-run compaction, bounded history, and startup orphan cleanup. A worker retains its content until its process exits, even after cancellation.
- `src/server.mjs`: loopback API and SSE status updates; token, Host/Origin validation. No apply/undo endpoints.
- `src/input.mjs`: shared 256,000-byte JSON ingress limit; decode complete UTF-8 bytes strictly and replace parser errors with generic diagnostics that contain no input snippets.
- `native/AutoReview.swift`, `src/widget.mjs`: optional macOS AppKit floating panel, menu bar entry, local WKWebView. Closing the panel leaves a clickable launcher. Both follow Codex foreground/visible-window state; switching apps hides them and preserves their expanded/collapsed state. Its narrow message bridge only collapses the panel and updates a bounded pending-report badge; it cannot run commands received from page content. Other platforms use the compact web panel.

A new main message does not cancel or wait for a running immutable review. The first prompt captures a turn baseline; steering messages retain that baseline and can also drain newly completed reports. Every successful review, including a clean result, pushes a reference into `state.adviceQueue`. Automatic reports are eligible only in their original project/session; manual reports are eligible for the next message in their project. New reports never replace older completed reports. Changed source sets `sourceChanged` and requires the main agent to recheck; it does not discard the report.

Batching serializes complete reports in FIFO order with a hard 48,000 UTF-16-character limit, including the instruction wrapper and JSON metadata. Whole reports that do not fit stay queued for the next message. Individual new reports are capped at 6,000 characters. The hook also checks the cap before writing stdout, and its official `additionalContextLimit=0` prevents a second host-side spill/truncation pass. Failed/cancelled/incomplete reviews do not enter the advice queue.

Queue references and delivered timestamps are persisted with the same atomic state write. Pending reports are exempt from pruning. At 200 pending reports plus live jobs, the engine rejects new review requests with an actionable message, preserving existing reports. Already queued code snapshots are separately limited to 20; a newer queued snapshot replaces an older not-yet-started snapshot in that session. The report queue and the snapshot execution queue are different structures.

The daemon is the only state writer. Synchronous state/capture transitions cannot interleave with one another inside Node; model work remains asynchronous. Arbitrary external editor changes during snapshot capture can fail that capture and are reported through the hook warning. Source changes during a user's turn cannot be attributed exclusively to the agent.

The plugin uses official additionalContext, not literal prompt rewriting. Its content is developer-context transport containing explicitly untrusted findings; the wrapper instructs the main agent to verify them and honor the current user request. Installation registers only this plugin’s exact hook hashes through the configuration API, then verifies the result. This short-lived control process does not refresh the desktop host's existing sessions. New tasks load the configuration; the desktop plugin toggle can reload its own host. The authenticated settings endpoint opens a fixed official plugin link from saved installation metadata, never a request-supplied URL. Preparing a hook response retains its reports in the queue. The dispatcher acknowledges a complete stdout write using a session/turn-bound receipt, after which the service records delivery. Lost responses and missing acknowledgements retry; duplicates are possible. This confirms transport handoff, not host parsing or model consumption, and cannot guarantee delivery across a later host crash.

State, temporary snapshots and reports live in `~/.autoreview`. Known credential paths are excluded, but source-embedded secrets or command output are not content-scanned. Isolated context and read-only sandboxing are not a claim of OS-level secrecy from a process running as the same user. No background installation/test jobs are configured or executed in v0.2.

The Stop hook captures immutable file bytes, including uncommitted changes. The reviewer materializes those exact bytes when its queue entry starts; it never re-captures the source project. Edits, deletions, and additions made after capture cannot alter its evidence or line numbers. The copy has an independent temporary Git repository, with no shared index, object store, hard links, or registered source worktree.

Success, failure, timeout, cancellation, and orderly shutdown all terminate and await the App Server process before deleting the workspace and its `.git`. POSIX termination covers its process group, escalating after 1.5 seconds; Windows uses `taskkill /T /F`. Garbage collection retains content referenced by queued/running reviews or active main-turn baselines. Finished baselines and unused blobs are released. Reports retain `snapshotDigest` for next-turn source-change markers, without retaining whole source copies or full review inputs.

On restart, unfinished reviews are cancelled without replaying model requests, terminal workspaces and orphan run directories are swept, and unused blobs and interrupted atomic-write files are removed. Forced process/OS termination can leave files until the next service start; this is startup recovery, not a guarantee that cleanup code executes after SIGKILL. Cleanup errors are visible in the panel and retried on later state transitions and a 15-minute maintenance timer.

Normal retained history excluding unconsumed reports is capped at 100 completed/cancelled/failed reviews and 200 inactive main turns, with at most 12 recent turns per session. Truncated requirements are explicitly marked. Active work and v1 recovery records are exempt from history eviction. `prune --days 30` remains available to remove older reports early; it is no longer required to release completed v0.2 source copies. Legacy snapshots, backups, and journals remain recovery evidence; unresolved legacy recovery flags block manual pruning.

The official Codex toolbar entry is `.codex/environments/environment.toml`, using an action named AutoReview with icon `tool`. It invokes a fixed command that resolves the user home at runtime, so no developer-specific absolute path is committed. `~/.autoreview/installation.json` tracks the installed cache path; the installer starts the daemon from that installed package. Complex pre-existing environment files are preserved and receive a manual add-action fallback in the panel. The companion and browser panel remain independent UI surfaces; the action does not register a native chat sidebar.

- `src/control.mjs`: short-lived official App Server client for per-definition AutoReview setup and verification, without a model turn.
- `src/attribution.mjs`: write-tool recognition, patch-file scope, before/after continuity and removal of files externally overwritten before Stop. Only attributed changes become review targets. Tool baselines and attributed bytes participate in reference cleanup.
- `desktop` launcher: receives the Codex Action working directory, connects/enables that project, records explicit launch context, and opens the companion. Project view selection does not modify project enablement.

## Cancellation and diagnostics (experiment round 4)

Completion metadata queries have their own abort controllers. Pausing/cancelling a candidate or stopping the service cancels the query and awaits its process tree. Each query uses at most the smaller of 20 seconds and the candidate’s remaining completion deadline; expired candidates never start another query. A terminal control connection rejects later requests immediately.

Shutdown aborts project activation, waits for its in-flight work, and prevents a late result from re-enabling the project. Requests recheck shutdown after reading their body. Shutdown responses use Connection: close, allowing the daemon to exit after its own response finishes. Failed listening releases the instance’s lock and event listeners. The lock carries an instance ID so cleanup does not blindly unlink another instance’s lock.

Hook errors are limited to 16,000 characters per entry. Hook writes, service startup, and maintenance trim diagnostic files above 1 MiB to their recent approximately 512 KiB of complete lines. Trimming is in place so an open append descriptor stays attached. This is a retention threshold, not a strict bound between concurrent writes or maintenance passes. Report queues are stored separately and are unaffected.
