# 审计完成但下一条消息没有收到意见

先区分三件事：安装配置已登记、宿主实际执行了 hook、主模型实际收到报告。面板“已开启”只说明项目允许审计；其他任务或 CLI 的事件不能证明当前 GUI 任务已接入。

## 已定位的原因与恢复

在 Codex CLI `0.154.0-alpha.6.2` 上，安装器用独立 App Server 进程登记插件并设置 `reloadUserConfig:true`，不能刷新桌面宿主已有会话的配置。即使新进程的 `hooks/list` 显示六个事件已启用、已信任，旧会话仍可能完全不调用它们。这会同时阻断自动审计触发和报告传达。

安装或升级后使用新任务即可加载。需要继续旧任务时，在 AutoReview 面板点击 **接入帮助 → 打开 Codex 插件页**，在 Codex 中将 AutoReview **关闭再开启一次**。这个官方开关由桌面宿主执行配置刷新。无需手动进入 CLI 信任 hook，也不需要编辑 Codex 内部文件。

打开插件页本身不刷新配置；面板“核对配置”只负责安装与信任登记。若本地安装来源已移动，链接会明确报错，可直接从 Codex 的插件列表进入 AutoReview。

另一个已修复问题发生在 macOS：补丁路径 `/var/folders/...` 与 Git 返回的 `/private/var/folders/...` 实际是同一目录，旧实现把前者误判为越界，导致 `no_attributed_codex_changes`。现在识别根目录的别名，仍拒绝仓库内部链接和真正越界的文件。

## 排查顺序

1. **没有 UserPromptSubmit 事件**：检查任务是否创建于安装前；通过上述桌面开关刷新或使用新任务。重新执行独立安装器不能替代桌面宿主刷新。
2. **有事件但没有自动审计**：本轮须有可识别的 Codex 写入、配对的前后工具事件、最终 Stop 和同一回合的 completed 证据。手工修改、只读工具或未结束回合不会触发。macOS 根路径别名的漏记已修复。
3. **报告还在运行**：下一条消息不会等待。完成报告在后续消息中传达。
4. **报告已完成但本轮没领取**：自动报告只给原项目、原会话；手动报告给该项目的下一条消息。单批最多 48,000 字符，剩余内容保留。
5. **已交接但无法确认模型收到**：stdout 成功回执仅证明管道交接。真实验收应在下一条消息中让主模型直接说明附加上下文中的 reviewId 与问题摘要，不能通过读取状态文件或 MCP 报告接口代替。

## 可复现实验与边界

`node scripts/probe-session-loading.mjs --external-reload` 使用真实官方 App Server、隔离 CODEX_HOME 和本地模拟模型端点；不读取或复制认证，不调用真实模型。安装前创建的会话在外部进程安装后没有事件，发送给模型端点的请求也没有报告标记；新会话以及同宿主刷新后的旧会话都有事件和标记。这个实验验证配置加载与传输行为，不能冒充 GUI 验收。

`node scripts/probe-hook-transport.mjs` 使用当前账号、真实 CLI、真实模型和隔离项目，确认模型能复述仅存在于注入上下文的随机标记，并验证真实代码写入被归因。它使用预置合成报告，不评价真实审计质量，也不是 GUI 实验。两种探针结束后删除临时项目、数据和副本。

实际 GUI 验收还需要在已刷新或新建的 GUI 任务中完成：正常改动 → 本轮工作和回答完成 → 后台真实审计完成 → 下一条消息通过 hook 收到同一报告。不能把 CLI 或模拟端点结果直接计为这一项通过。
